# 4.2 WdgM Source Walkthrough: Triple Supervision as a C State Machine

## Scenario: When the Scheduler Wakes Up MainFunction

Just past nine in the morning, the ECU's OS counter ticks away. In the 10 ms periodic task queue, `WdgM_MainFunction` wakes up. It is only about fifty lines long, yet in this one pass it has to walk every supervised entity configured in the current mode, aggregate local states, compute the global state, and finally decide whether to put the whole ECU into STOPPED and trigger a hardware watchdog reset.

You open `WdgM.c` and read line by line. Comments like `/** @req SWS_WdgM_00011 */` are everywhere; every piece of code traces back to a specific requirement in the AUTOSAR specification. This is not "I think it should be written this way" code. It is code that implements each requirement item of the AUTOSAR 4.3.0 specification one by one.

Before reading it line by line, look at the overall skeleton. WdgM's 1450 lines fall into three layers:

**The bottom layer (configuration)**: `WdgM_ConfigTypes.h` uses a chain of const structs to fix the shape of every supervised entity's (SE's) parameters: the expected count and upper/lower tolerances for alive supervision, the min and max for deadline supervision, the number of allowed failure cycles, the checkpoint transition table for logical supervision, the initial mode ID, and the trigger value and operating mode of the watchdog in each mode. This layer executes no logic; it only stores "rules".

**The middle layer (execution)**: `WdgM_MainFunction()` is the core entry point, called once per scheduling cycle. In about fifty lines it evaluates alive supervision and aggregates each SE's three substates (Alive / Deadline / Logical) into a local state (OK/FAILED/EXPIRED/DEACTIVATED), then derives the global state from the local states. The deadline and logical substates were already refreshed inside `WdgM_CheckpointReached()` with each checkpoint report.

**The top layer (response)**: when any SE stays timed out long enough to hit the tolerance limit, `WdgM_MainFunction()` sets the global state to STOPPED, the hardware watchdog stops being fed, and the countdown reaching zero triggers a reset. This is the last strike — the software layer no longer trusts itself and hands the decision to hardware.

The three layers chain together as: **follow the configuration rules → check every cycle → suicide on timeout**. Below we start at Init and walk every layer in execution order.

## 1. Opening: Instantiation and Macro Armament

At the top of the file you see a piece of guard code with zero runtime cost:

```c
#if !(((WDGM_SW_MAJOR_VERSION == 3u) && (WDGM_SW_MINOR_VERSION == 0u)) )
#error WdgM: Expected BSW module version to be 3.0.*
#endif

#if !(((WDGM_AR_RELEASE_MAJOR_VERSION == 4u) && (WDGM_AR_RELEASE_MINOR_VERSION == 3u)) )
#error WdgM: Expected AUTOSAR version to be 4.3.*
#endif
```

This is AUTOSAR's "compile-time contract". If an integrator mixes WdgM 3.0 headers with an inconsistent AUTOSAR version, the compiler simply refuses. Production code has no "runtime assert", only `#error`.

Then the first group of macros: **dual compilation** of parameter checks:

```c
#if (WDGM_DEV_ERROR_DETECT == STD_ON)

#define WDGM_CHECK_INIT_NO_RV(functionID)                              \
    {                                                               \
        if (WdgM_instance.isInitiated == (boolean)FALSE)            \
        {                                                           \
            WDGM_REPORT_DET_ERROR(functionID, WDGM_E_NO_INIT);      \
            return;                                                 \
        }                                                           \
    }
// ... 9 check macros in total ...

#else

#define WDGM_CHECK_INIT_NO_RV(functionID)                          \
    {                                                           \
        if (WdgM_instance.isInitiated == (boolean)FALSE)        \
        {                                                       \
            return;                                             \
        }                                                       \
    }
```

When `WDGM_DEV_ERROR_DETECT == STD_ON`, the macro expands to the full version with a DET report. When it is off, the macro keeps only the safety check, **with zero DET overhead**. But the point is not performance. During development, every out-of-range parameter is caught by DET immediately; in production the safety check still runs (it just does not report to DET). The source even leaves a note on this two-macro, configuration-switch approach, admitting that "check, then return immediately" does not fully agree with one requirement in the standard.

The `/*lint -e904 */` annotation for MISRA C:2012 Rule 15.5 appears throughout the file. It is a formal deviation for the "early return breaks the single function exit" rule. Arctic Core chooses "check for errors first, return immediately" over nested ifs; readability wins over dogma.

## 2. Init: The Leap from Configuration to the Runtime World

`WdgM_Init()` is about 80 lines and is the entry point for understanding the whole module:

```c
void WdgM_Init(const WdgM_ConfigType *ConfigPtr)
{
    const WdgM_Mode *initialMode;
    uint16 i;
    boolean status = (boolean)TRUE;
    Std_ReturnType ret = E_OK;

    WDGM_CHECK_NULL_POINTER_NO_RV(ConfigPtr, WDGM_SID_INIT);
    WDGM_CHECK_DEINIT_NO_RV(WDGM_SID_INIT);

    WdgM_instance.ConfigPtr = ConfigPtr;
    WdgM_instance.runtimeDataPtr = &WdgM_runtimeData;
    initialMode = &WdgM_instance.ConfigPtr->ConfigSet.Modes[
        WdgM_instance.ConfigPtr->ConfigSet.initialModeId];
```

The first three steps reveal the core design: **configuration (ConfigPtr) is a const pointer that never changes; runtime data (runtimeDataPtr) is mutable and updated every MainFunction cycle**. This separation of "read-only configuration + mutable state" is a cornerstone of functional safety code. Configuration can live in Flash (physically read-only); state lives in RAM.

Next comes the "initialization insurance", which checks whether the initial mode really has a watchdog running:

```c
#if (WDGM_OFF_MODE_ENABLED != STD_ON)
    status = WdgM_internal_isAtLeastOneWdogEnabled(
        initialMode->Id, WDGM_SID_INIT, WDGM_E_DISABLE_NOT_ALLOWED);
#endif
```

If the configuration is wrong and every watchdog in the initial mode is set to OFF, Init reports DET and exits. The ECU will not start in a state where "the watchdog isn't on".

Then two loops: turn everything off first, then turn on only the initial mode:

```c
    for (i = 0u; i < WdgM_instance.ConfigPtr->General.Length_SupervisedEntities; i++)
    {
        WdgM_internal_DeactivateAndResetSE(i);
    }

    for (i = 0u; i < initialMode->Length_SEConfigurations; i++)
    {
        uint16 SEId = initialMode->SEConfigurations[i].SupervisedEntityId;
        WdgM_runtime_SupervisedEntity *runtime_se =
            &WdgM_instance.runtimeDataPtr->SEs[SEId];
        runtime_se->LocalState = WDGM_LOCAL_STATUS_OK;
        WdgM_Internal_ReportLocalModeChange(runtime_se, SEId);
    }
```

Finally, activate the hardware watchdog triggers of the initial mode:

```c
        ret = WdgM_internal_activateTriggers(
            initialMode,
            WdgM_instance.ConfigPtr->ConfigSet.DemEventIdRefs.SetMode);

        if (E_OK == ret)
        {
            WdgM_instance.isInitiated = (boolean)TRUE;
        }
```

One detail: `isInitiated` is set to TRUE only after the WdgIf trigger succeeds. If the hardware watchdog cannot start, WdgM's internal state is a "zombie module" that never starts, and most later API calls are blocked by the `WDGM_CHECK_INIT_*` macros; a few interfaces are deliberately exempt, such as the one that reads the first expired entity ID, whose source comment says it has to work before Init too. An incomplete initialization does not leave behind a state machine that "pretends to be working".

## 3. MainFunction: The Scheduling Miracle in Fifty Lines

This is the part you need to read closely, line by line:

```c
void WdgM_MainFunction( void )
{
    WDGM_CHECK_INIT_NO_RV(WDGM_SID_MAINFUNCTION);

    uint8 i;

    /* now do alive monitoring */
    WdgM_internal_CheckAlives();

    /* now do the other stuff */
    WdgM_internal_CalculateGlobalState();

    if (WdgM_instance.GlobalState == WDGM_GLOBAL_STATUS_STOPPED)
    {
#if (WDGM_DEM_ALIVE_SUPERVISION_REPORT == STD_ON)
        WDGM_REPORT_DEM_ERROR(
            WdgM_instance.ConfigPtr->ConfigSet.DemEventIdRefs.Supervision);
#endif
#if (WDGM_IMMEDIATE_RESET == STD_ON)
        Mcu_PerformReset();
#endif
    }

    /* set the triggers for all wdgdevices != WDGIF_OFF_MODE */
    for(i = 0u; i < WdgM_instance.CurrentMode->Length_Triggers; i++)
    {
        if (WdgM_instance.CurrentMode->Triggers[i].WatchdogMode
            != WDGIF_OFF_MODE)
        {
            uint16 triggerValue = (WdgM_instance.GlobalState
                == WDGM_GLOBAL_STATUS_STOPPED) ? 0u :
                WdgM_instance.CurrentMode->Triggers[i].TriggerConditionValue;
            if (WdgM_instance.ResetInitiated == (boolean)FALSE)
            {
                WdgIf_SetTriggerCondition(
                    WdgM_instance.ConfigPtr->General.Watchdogs[
                        WdgM_instance.CurrentMode->Triggers[i].WatchdogId
                    ].WatchdogDeviceId, triggerValue);
            }
        }
    }
}
```

Three steps: **CheckAlives → CalculateGlobalState → feed the dog or take revenge**.

The ternary operator in the last step is the key: `GlobalState == STOPPED ? 0u : TriggerConditionValue`. Once the global state lands on STOPPED, two things happen: first, if `WDGM_IMMEDIATE_RESET` is on, it calls `Mcu_PerformReset()` directly; then the loop drives the trigger value of every non-OFF watchdog to zero (provided a reset has not already been initiated). A hardware watchdog that is not fed resets on its own. This is the last line of defense for the fail-safe principle: even if the software crashes after STOPPED, the hardware timer expiring will reset the ECU.

## 4. Alive Check: The Survival Code in the Tolerance

`WdgM_internal_CheckAlives()` walks all SE configurations in the current mode, and every alive checkpoint goes through a two-stage judgment:

```c
static WdgM_Substate WdgM_internal_SpecAliveAlgo(
    const WdgM_AliveSupervision *aliveCP,
    WdgM_runtime_AliveSupervision *runtimeAliveCP)
{
    WdgM_Substate retVal = WDGM_SUBSTATE_INCORRECT;

    sint16 temp = (sint16)runtimeAliveCP->AliveCounter
                - (sint16)aliveCP->ExpectedAliveIndications;

    if ((temp <= (sint16)aliveCP->MaxMargin)
        && (temp >= (0 - (sint16)aliveCP->MinMargin)))
    {
        retVal = WDGM_SUBSTATE_CORRECT;
    }

    runtimeAliveCP->AliveCounter = 0u;
    runtimeAliveCP->SupervisionCycleCounter = 0u;

    return retVal;
}
```

Core algorithm: use a signed integer to compute `actual alive count - expected value`, then verify that it lies in `[-MinMargin, +MaxMargin]`. For example, with an expected 5 checkpoints, MinMargin=1, and MaxMargin=1, both 4 and 6 are OK. **Tolerance is not a performance optimization; it is a safety design**. OS scheduling jitter and interrupt latency can both cause one extra MainFunction cycle.

The trigger condition is `SupervisionReferenceCycle`:

```c
static WdgM_Substate WdgM_internal_IsAliveHold(
    const WdgM_AliveSupervision *aliveCP,
    WdgM_runtime_AliveSupervision *runtime_aliveCP)
{
    if (aliveCP->SupervisionReferenceCycle == 1u)
    {
        /* each cycle */
        retVal = WdgM_internal_SpecAliveAlgo(aliveCP, runtime_aliveCP);
    }
    else
    {
        if (runtime_aliveCP->SupervisionCycleCounter
            == aliveCP->SupervisionReferenceCycle)
        {
            retVal = WdgM_internal_SpecAliveAlgo(aliveCP, runtime_aliveCP);
        }
    }
}
```

You can set SupervisionReferenceCycle to 1 (check every MainFunction cycle) or to a larger value (say 5, checking every 5 cycles). This is a "grace period" for slow SEs; not every task runs on a 10 ms cycle.

## 5. Deadline Check: The Time Judge of the OS Counter

Deadline supervision uses the AUTOSAR OS standard interface `GetElapsedValue()`:

```c
static WdgM_Substate WdgM_internal_DeadlineMonitoring(
    const WdgM_SupervisedEntityConfiguration *seConf,
    const WdgM_runtime_SupervisedEntityConfig *runtime_seConf,
    WdgM_CheckpointIdType CPId)
{
    WdgM_Substate result = WDGM_SUBSTATE_CORRECT;

    for(i = 0u; i < seConf->Length_DeadlineSupervisions; i++)
    {
        if (seConf->DeadlineSupervisions[i].CheckpointIdStart == CPId)
        {
            TickType elapsedTicks = 0u;
            TickRefType elapsedTicksPointer;
            elapsedTicksPointer = &elapsedTicks;
            TickRefType LastTickPointer = (TickRefType)
                &(runtime_seConf->DeadlineSupervisions[i].LastTickValue);
            (void)GetElapsedValue(seConf->OSCounter,
                LastTickPointer, elapsedTicksPointer);
        }

        if ((seConf->DeadlineSupervisions[i].CheckpointIdFinish == CPId)
            && (runtime_seConf->DeadlineSupervisions[i].LastTickValue != 0u))
        {
            if (WdgM_internalIsDeadlineHold(seConf->OSCounter,
                &seConf->DeadlineSupervisions[i],
                &runtime_seConf->DeadlineSupervisions[i])
                == WDGM_SUBSTATE_INCORRECT)
            {
                result = WDGM_SUBSTATE_INCORRECT;
                break;
            }
            runtime_seConf->DeadlineSupervisions[i].LastTickValue = 0u;
        }
    }
    return result;
}
```

When the start checkpoint arrives, it records the OS instant (reads the current count via `GetElapsedValue`); when the finish checkpoint arrives, it reads again and computes the difference:

```c
#define WDGM_OSTICKSPERSECOND (1000000000UL / OSTICKDURATION)  /* ticks per second */

static WdgM_Substate WdgM_internalIsDeadlineHold(
    const CounterType counter_id,
    const WdgM_DeadlineSupervision *deadlineCP,
    WdgM_runtime_DeadlineSupervision *runtime_deadlineCP)
{
    TickType elapsedTicks = 0u;
    // ... GetElapsedValue ...
    if ((elapsedTicks >=
         (deadlineCP->DeadlineMin * WDGM_OSTICKSPERSECOND))
        && (elapsedTicks <=
         (deadlineCP->DeadlineMax * WDGM_OSTICKSPERSECOND)))
    {
        ret = WDGM_SUBSTATE_CORRECT;
    }
    return ret;
}
```

Working backward from this multiplication, DeadlineMin / DeadlineMax in the configuration are in seconds; multiplying by ticks per second converts them to OS ticks. `OSTICKDURATION` gives how many nanoseconds one tick is; a billion divided by it is ticks per second. When the tick period is 1 microsecond, that multiplier is exactly one million, and 1 second in the configuration maps to one million ticks.

## 6. Logical Check: Transition Table Verification

The heart of logical supervision is a directed graph, the `Transitions[]` array defined in `WdgM_SupervisedEntity`:

```c
static WdgM_Substate WdgM_internal_LogicalMonitoring_GraphActive(
    const WdgM_SupervisedEntity *se,
    WdgM_runtime_SupervisedEntity *runtime_se,
    WdgM_CheckpointIdType CPId)
{
    WdgM_Substate retVal = WDGM_SUBSTATE_INCORRECT;

    for(i = 0u; i < se->Length_Transitions; i++)
    {
        if(se->Transitions[i].CheckpointIdSource
           == runtime_se->PreviousCheckpointId_internalLogic)
        {
            if(se->Transitions[i].CheckpointIdDestination == CPId)
            {
                retVal = WDGM_SUBSTATE_CORRECT;
                runtime_se->PreviousCheckpointId_internalLogic = CPId;
                break;
            }
        }
    }

    if (retVal == WDGM_SUBSTATE_CORRECT)
    {
        for(i = 0u; i < se->Length_FinalCheckpointIds; i++)
        {
            if (se->FinalCheckpointIds[i] == CPId)
            {
                runtime_se->IsInternalGraphActive = (boolean)FALSE;
                break;
            }
        }
    }
    return retVal;
}
```

The logic has two layers: if the graph is active (`IsInternalGraphActive == TRUE`), every checkpoint must connect to the previous checkpoint through a defined transition edge. When a FinalCheckpoint is reached, the graph becomes inactive and waits for the next StartCheckpoint to reactivate it.

This mechanism catches program-flow tampering: if an SE normally runs CP1→CP2→CP3 but one time goes CP1→CP4 (CP4 is not in the legal transition table), logical supervision catches it immediately. In principle it is a small **control flow checking (CFC)** implementation built from plain C data structures.

## 7. Global State Aggregation: From Local to Global

`WdgM_internal_CalculateGlobalState()` walks all SEs and aggregates their states:

```c
static void WdgM_internal_CalculateLocalState(
    WdgM_runtime_SupervisedEntity *runtime_se,
    const WdgM_SupervisedEntityConfiguration *seConf,
    const WdgM_runtime_SupervisedEntityConfig *runtime_seConf)
{
    uint8 nrOfCorrectSubstates = runtime_se->SubstateAlive
        + runtime_se->SubstateDeadline + runtime_se->SubstateLogical;

    switch (nrOfCorrectSubstates) {
        case WDGM_ALLSUBSTATECORRECT:   // = 3
            break;
        case WDGM_ONESUBSTATEINCORRECT: // = 2
            if (runtime_se->LocalState == WDGM_LOCAL_STATUS_OK)
            {
                WdgM_internal_CalculateLocalState_FromOKOneError(...);
            }
            if (runtime_se->LocalState == WDGM_LOCAL_STATUS_FAILED)
            {
                WdgM_internal_CalculateLocalState_FromFailedOneError(...);
            }
            break;
        default:  // 0 or 1 substates correct
            runtime_se->LocalState = WDGM_LOCAL_STATUS_EXPIRED;
            break;
    }
}
```

One elegant design: Substate is defined as `#define WDGM_SUBSTATE_CORRECT (WdgM_Substate)0x01` . So `SubstateAlive + SubstateDeadline + SubstateLogical` is the number of correct substates! Add them up and switch-case directly. 0-1 correct → EXPIRED immediately; 2 correct → enter the tolerance calculation (FailedAliveCyclesCounter); 3 correct → back on the healthy track: if already on OK, do nothing; if still stuck on FAILED, decrement the failure count one notch first, and only release it back to OK when the count bottoms out.

Then the global state transition logic, starting from Global OK:

```c
static void WdgM_internal_updateFromGlobalOK(uint16 expired, uint16 failed)
{
    if (failed > 0u)
    {
        WdgM_instance.GlobalState = WDGM_GLOBAL_STATUS_FAILED;
    }
    if (expired > 0u) {
        if (WdgM_instance.runtimeDataPtr->Modes[
            WdgM_instance.CurrentMode->Id].ExpiredSupervisionCycleCounter
            < WdgM_instance.CurrentMode->ExpiredSupervisionCycleTol) {
            WdgM_instance.GlobalState = WDGM_GLOBAL_STATUS_EXPIRED;
        } else {
            WdgM_instance.GlobalState = WDGM_GLOBAL_STATUS_STOPPED;
        }
    }
}
```

Any SE EXPIRED? Enter EXPIRED first and give the system the last `ExpiredSupervisionCycleTol` MainFunction cycles to save itself. After the timeout → STOPPED → the watchdog starves → reset. Note that the global state has five possible values: OK, FAILED, EXPIRED, STOPPED, DEACTIVATED. DEACTIVATED is the instance's factory setting, and `WdgM_DeInit()` also returns the state there.

## 8. Redundant Inverted Storage: A Six-Line Safety Highlight

In `WdgM_MainFunction` → `WdgM_internal_CalculateGlobalState`, you see this block:

```c
    if (WdgM_instance.isFirstExpiredSet == (boolean)FALSE)
    {
        firstExpiredSEID = i;
        firstExpiredSEIDInverse = ~i;
        WdgM_instance.isFirstExpiredSet = (boolean)TRUE;
    }
```

And in `WdgM_GetFirstExpiredSEID`:

```c
    uint16 invertedSEID = (~firstExpiredSEID);

    if (invertedSEID == firstExpiredSEIDInverse) {
        *SEID = firstExpiredSEID;
        retVal = E_OK;
    } else {
        *SEID = 0u;
        retVal = E_NOT_OK;
    }
```

This is **fault detection through redundant storage**: store the same value `i` as `firstExpiredSEID` and its bitwise inverse `firstExpiredSEIDInverse`. On read, recompute the inverse and compare. If any bit in RAM silently flips, the inverted value no longer matches and the function returns `E_NOT_OK`. This kind of trick is also often mentioned alongside engineering practice in high-reliability aerospace systems.

WdgM's 1450 lines of C implement a complete closed loop of fault detection → state transition → trigger response. From the micro level of redundant storage (inverse check) to the middle level of tolerance arithmetic (-MinMargin/+MaxMargin) to the macro level of the state machine (OK→FAILED→EXPIRED→STOPPED, plus the fifth value DEACTIVATED that guards before init and after deinit), every layer follows the fail-safe principle of "detect → tolerate → escalate → reset". It is not "panic as soon as an anomaly is detected". It gives the system several chances to save itself and only performs the final reset once recovery is certain to be impossible.

## Summary

1. WdgM's 1450 lines split into a three-layer architecture: configuration (const structs define the rules) → execution (`WdgM_MainFunction` evaluates aliveness and aggregates state in about fifty lines, while the deadline and logical substates were refreshed earlier by `WdgM_CheckpointReached()`) → response (once the global state is STOPPED, the hardware watchdog starves and resets), following the fail-safe loop of "follow the configuration rules → check every cycle → suicide on timeout".
2. Init uses a two-loop strategy: "turn everything off first, then enable only the initial mode". The `isInitiated` flag is set to TRUE only after WdgIf activation succeeds, which rules out any "zombie module".
3. Alive supervision implements tolerance as a signed-integer comparison of `actual count - expected value ∈ [-MinMargin, +MaxMargin]`. Tolerance is a safety design, not a performance optimization — it absorbs OS scheduling jitter and interrupt latency.
4. Deadline and Logical supervision use the OS counter and a directed-graph transition table to catch time violations and program-flow tampering. Global-state aggregation exploits the macro values of `Substate` (0x01): adding them and switching on the sum means 0–1 correct → EXPIRED immediately, 2 → tolerance calculation, 3 → back to OK (if the entity was on FAILED, the code decrements the failure count to the bottom before releasing it). The global state has five values in total; the extra DEACTIVATED is where the instance sits before initialization and after DeInit.
5. Redundant inverted storage (`firstExpiredSEID` holds the original, `firstExpiredSEIDInverse` holds the bitwise inverse; on read the code inverts again and compares) is six lines long and catches single-bit flips in those two static variables — fail-safe design at the micro level.
