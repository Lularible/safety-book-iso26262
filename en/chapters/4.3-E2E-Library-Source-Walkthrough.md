# 4.3 E2E Library Source Walkthrough: The Shared Skeleton of Five Profiles

## Scenario: When a CAN Frame Reaches the ECU

The ECU's CAN controller receives a frame from the bus: 8 bytes holding the current value of the steering-angle sensor. Those 8 bytes start in the sensor MCU's RAM, travel over the SPI bus, the CAN transceiver, a differential cable, another CAN transceiver, and the ECU's internal bus, and finally arrive at your application SW-C. Along the way the data meets electromagnetic interference, voltage fluctuations, and transceiver faults. Any single bit flip can make the steering wheel "see" the wrong angle.

AUTOSAR defines an end-to-end (E2E) protection protocol for exactly this. Arctic Core's E2E library covers 5 profiles (P01/P02/P04/P05/P06); the source directory holds the five profile source files plus the shared part `E2E.c` and the state machine `E2E_SM.c`. Today we open the full P01 implementation.

## 1. E2E.h: The Shared Contract

Start with `E2E.h`, the common interface of all profiles and the state machine:

```c
/** @file E2E.h
 *  The E2E library provides
 *      *The definition of profiles 1,2,4,5 and 6 including check
 *       and protect functions
 *      *A state machine describing the logical algorithm of E2E
 *       monitoring independent of the used profile
 */

/* The E2E library shall not call any functions from external
 * modules apart from explicitly listed expected interfaces: Crc */
#include "Crc.h"
#include "Std_Types.h"
```

The key constraint is in the comment: **the E2E library calls no RTE, no BSW modules (DEM/DET), and reports no errors**. It is a pure function library: data and state in, checksum and state updates out. All errors travel through return values. This is what lets the E2E library be developed and certified independently as a Safety Element out of Context (SEooC).

Common error codes:

```c
#define E2E_E_INPUTERR_NULL     0x13   // NULL pointer
#define E2E_E_INPUTERR_WRONG    0x17   // parameter out of range
#define E2E_E_INTERR            0x19   // internal error
#define E2E_E_OK                0x00   // success
#define E2E_E_WRONGSTATE        0x1A   // state machine not initialized
```

Module version check, paired with the Crc library:

```c
#if (E2E_AR_RELEASE_MAJOR_VERSION != CRC_AR_RELEASE_MAJOR_VERSION) \
    || (E2E_AR_RELEASE_MINOR_VERSION != CRC_AR_RELEASE_MINOR_VERSION)
#error "SW Version mismatch between E2E.h and Crc.h"
#endif
```

If the integration stage mixes AUTOSAR 4.2 E2E headers with a 4.3 Crc library, the compiler errors out.

## 2. E2E_P01.c: The Full Picture of Profile 1

Profile 1 is the most common E2E configuration in A-SPICE and ISO 26262. Its protection chain has only three items:

1. **CRC-8-SAE J1850** (polynomial 0x1D, Start=0x00, XOR=0x00)
2. **4-bit Counter** (cycles from 0 to 14, skipping 0xF)
3. **DataID** (1 byte or 2 bytes, 4 modes)

The file opens with a series of compile-time constraints:

```c
#define MAX_P01_DATA_LENGTH_IN_BITS    (240)    // max 30 bytes
#define MAX_P01_COUNTER_VALUE          (14)     // counter skips 0xF

#define Crc_8_Xor                      0xFFU
```

Double version check, source file vs header file:

```c
#if (E2E_P01_SW_MAJOR_VERSION != E2E_P01_SW_MAJOR_VERSION_INT) \
    || (E2E_P01_SW_MINOR_VERSION != E2E_P01_SW_MINOR_VERSION_INT)
#error "SW Version mismatch between E2E_P01.c and E2E_P01.h"
#endif

#if (E2E_P01_AR_RELEASE_MAJOR_VERSION != E2E_P01_AR_RELEASE_MAJOR_VERSION_INT) \
    || ...
#error "AR Version mismatch between E2E_P01.c and E2E_P01.h"
#endif
```

This is the file-level version consistency check AUTOSAR mandates. You will see this pattern in every source file of Arctic Core.

## 3. The Configuration Checker: checkConfigP01

Before Protect and Check run, the configuration itself must pass an integrity check:

```c
static INLINE Std_ReturnType checkConfigP01(const E2E_P01ConfigType* Config)
{
    Std_ReturnType status;
    status = E2E_E_OK;

    if (Config == NULL_PTR) {
        status = E2E_E_INPUTERR_NULL;
    }
    else if ((Config->DataLength > MAX_P01_DATA_LENGTH_IN_BITS)
        || ((Config->DataLength % 8) != 0)
        || ((Config->CounterOffset % 4) != 0)
        || ((Config->CRCOffset % 8) != 0)) {
        status = E2E_E_INPUTERR_WRONG;
    }
    else if (((Config->CRCOffset + 8) > Config->DataLength)
        || ((Config->CounterOffset + 4) > Config->DataLength)
        || ((Config->CRCOffset/8) == (Config->CounterOffset/8))) {
        status = E2E_E_INPUTERR_WRONG;
    }
    else if ((Config->DataIDMode != E2E_P01_DATAID_NIBBLE)
        && (Config->DataIDNibbleOffset != 0)) {
        status = E2E_E_INPUTERR_WRONG;
    }
    else if ((Config->DataIDMode == E2E_P01_DATAID_LOW)
        && ((Config->DataID>>8) != 0)) {
        status = E2E_E_INPUTERR_WRONG;
    }
    else if ((Config->DataIDMode == E2E_P01_DATAID_NIBBLE)
        && ((Config->DataID>>12) != 0)) {
        status = E2E_E_INPUTERR_WRONG;
    }
    // ... return E2E_E_OK
    return status;
}
```

The checklist:

- CRC and Counter must not overlap in the same byte
- The CRC position must lie within the data (`CRCOffset+8 <= DataLength`)
- The Counter must be 4-bit aligned (offset %4 == 0)
- DataID fields must be legal: in `LOW` mode the high byte of DataID must be 0, in `NIBBLE` mode the high 4 bits of the high byte must be 0, and in the other modes `DataIDNibbleOffset` must be 0

If the configuration data is silently corrupted (say a constant in Flash flips), checkConfigP01 catches it on the first call.

## 4. CRC Calculation: A Mathematical Signature Across DataID and Data

```c
static uint8 calculateCrcP01(const E2E_P01ConfigType* Config,
    uint8 Counter, const uint8* Data)
{
    uint8 crc = 0x00u ^ Crc_8_Xor;  /* Need to cancel first XOR in CRC */
    uint8 lowerByteId = (uint8)Config->DataID;
    uint8 upperByteId = (uint8)(Config->DataID>>8);

    /* Calculate CRC on the Data ID */
    if (Config->DataIDMode == E2E_P01_DATAID_BOTH)
    {
        crc = Crc_CalculateCRC8(&lowerByteId, 1, crc, FALSE);
        crc = Crc_CalculateCRC8(&upperByteId, 1, crc, FALSE);
    }
    else if (Config->DataIDMode == E2E_P01_DATAID_LOW)
    {
        crc = Crc_CalculateCRC8(&lowerByteId, 1, crc, FALSE);
    }
    else if (Config->DataIDMode == E2E_P01_DATAID_NIBBLE)
    {
        crc = Crc_CalculateCRC8(&lowerByteId, 1, crc, FALSE);
        upperByteId = 0;
        crc = Crc_CalculateCRC8(&upperByteId, 1, crc, FALSE);
    }
    else if ((Counter % 2) == 0) // E2E_P01_DATAID_ALT: even
    {
        crc = Crc_CalculateCRC8(&lowerByteId, 1, crc, FALSE);
    }
    else // E2E_P01_DATAID_ALT: odd counter
    {
        crc = Crc_CalculateCRC8(&upperByteId, 1, crc, FALSE);
    }

    /* Calculate CRC on the data (skip the CRC byte itself) */
    if (Config->CRCOffset >= 8) {
        crc = Crc_CalculateCRC8(Data,
            (Config->CRCOffset / 8), crc, FALSE);
    }
    if ((Config->CRCOffset / 8) < ((Config->DataLength / 8) - 1)) {
        crc = Crc_CalculateCRC8(
            &Data[(Config->CRCOffset/8) + 1],
            (((Config->DataLength / 8) - (Config->CRCOffset / 8)) - 1),
            crc, FALSE);
    }

    return crc ^ Crc_8_Xor;  /* Need to cancel last XOR in CRC */
}
```

Key design details:

1. **The CRC library's default start value is 0xFF, but E2E P01 requires 0x00**, so `crc = 0x00 ^ 0xFF` cancels the first XOR. Before returning, the function XORs 0xFF once more to cancel the library's final XOR, so the final XOR value also lands on 0x00.
2. **The CRC byte itself does not participate**, the data is split into the part before the CRC and the part after it, each fed into `Crc_CalculateCRC8`.
3. **The 4 DataID modes**:
   - `BOTH`: both low byte and high byte participate in the CRC
   - `LOW`: only the low byte (high byte is 0x00)
   - `NIBBLE`: the CRC first covers the low byte, then covers a byte forced to zero; the low 4 bits of the high byte are written into the data via `DataIDNibbleOffset` and are protected along with the data, and the high 4 bits must be 0x0 (variant 1C)
   - `ALT`: alternates between the low byte and the high byte according to the parity of Counter (variant 1B)

## 5. Protect: The Sender's Armor

```c
Std_ReturnType E2E_P01Protect(const E2E_P01ConfigType* ConfigPtr,
    E2E_P01ProtectStateType* StatePtr, uint8* DataPtr)
{
    Std_ReturnType status;
    status = E2E_E_OK;
    Std_ReturnType returnValue = checkConfigP01(ConfigPtr);

    if (E2E_E_OK != returnValue) {
        status = returnValue;
    }
    else if ((StatePtr == NULL_PTR) || (DataPtr == NULL_PTR)) {
        status = E2E_E_INPUTERR_NULL;
    }
    else {
        /* Put counter in data */
        if ((ConfigPtr->CounterOffset % 8) == 0) {
            DataPtr[ConfigPtr->CounterOffset/8] =
                (DataPtr[(ConfigPtr->CounterOffset/8)] & 0xF0u)
                | (StatePtr->Counter & 0x0Fu);
        }
        else {
            DataPtr[ConfigPtr->CounterOffset/8] =
                (DataPtr[ConfigPtr->CounterOffset/8] & 0x0Fu)
                | ((StatePtr->Counter<<4) & 0xF0u);
        }

        /* Put counter in data for E2E_P01_DATAID_NIBBLE */
        if (ConfigPtr->DataIDMode == E2E_P01_DATAID_NIBBLE) {
            if ((ConfigPtr->DataIDNibbleOffset % 8) == 0) {
                DataPtr[ConfigPtr->DataIDNibbleOffset/8] =
                    (DataPtr[(ConfigPtr->DataIDNibbleOffset/8)] & 0xF0u)
                    | ((uint8)((ConfigPtr->DataID>>8) & 0x0Fu));
            }
            else {
                DataPtr[ConfigPtr->DataIDNibbleOffset/8] =
                    (DataPtr[ConfigPtr->DataIDNibbleOffset/8] & 0x0Fu)
                    | ((uint8)((ConfigPtr->DataID>>4) & 0xF0u));
            }
        }

        /* Calculate CRC */
        DataPtr[(ConfigPtr->CRCOffset/8)] =
            calculateCrcP01(ConfigPtr, StatePtr->Counter, DataPtr);

        /* Update counter */
        StatePtr->Counter = (StatePtr->Counter+1) % 15;
    }
    return status;
}
```

Protect's three steps:

1. **Embed the Counter**: use `& 0xF0 | Counter` or `& 0x0F | Counter<<4` to place the 4-bit counter into the nibble at the configured offset
2. **Compute and embed the CRC**: call `calculateCrcP01` and write the whole CRC8 into the configured byte
3. **Update the counter**: `(Counter+1) % 15`, skipping 0xF (15), so 0xE goes straight back to 0x0

Pay special attention to the bit operations for the Counter offset: the Counter is 4-bit aligned, and the code must decide from the offset whether it occupies the low or high nibble. `(ConfigPtr->CounterOffset % 8) == 0` tests for a byte boundary: on a byte boundary it uses the low nibble, otherwise the high nibble. There is no "guesswork" in this code; every bit position is decided by compile-time configuration.

## 6. Check: The Receiver's Graph Algorithm

The complete state machine logic of `E2E_P01Check` (corresponding to the E2E state machine figure in the AUTOSAR specification):

```c
Std_ReturnType E2E_P01Check(const E2E_P01ConfigType* ConfigPtr,
    E2E_P01CheckStateType* StatePtr, const uint8* DataPtr)
{
    Std_ReturnType status;
    status = E2E_E_OK;
    boolean ret;
    ret = TRUE;
    uint8 receivedCounter;
    uint8 receivedCrc;
    uint8 calculatedCrc;
    uint8 receivedDataIDNibble;
    Std_ReturnType returnValue = checkConfigP01(ConfigPtr);

    if (E2E_E_OK != returnValue) { status = returnValue; }
    else if ((StatePtr == NULL_PTR) || (DataPtr == NULL_PTR)) {
        status = E2E_E_INPUTERR_NULL;
    }
    else {
        /* MaxDeltaCounter increment before check */
        if (StatePtr->MaxDeltaCounter < MAX_P01_COUNTER_VALUE) {
            StatePtr->MaxDeltaCounter++;
        }

        if (StatePtr->NewDataAvailable == FALSE) {
            if (StatePtr->NoNewOrRepeatedDataCounter
                < MAX_P01_COUNTER_VALUE) {
                StatePtr->NoNewOrRepeatedDataCounter++;
            }
            StatePtr->Status = E2E_P01STATUS_NONEWDATA;
            status = E2E_E_OK;
            ret = FALSE;
        }

        if (ret == TRUE) {
            receivedCounter = readCounterP01(ConfigPtr, DataPtr);
            if (receivedCounter > MAX_P01_COUNTER_VALUE) {
                status = E2E_E_INPUTERR_WRONG;
            } else {
                receivedCrc = DataPtr[(ConfigPtr->CRCOffset/8)];
                receivedDataIDNibble =
                    readDataIDNibbleOffsetP01(ConfigPtr, DataPtr);
                calculatedCrc =
                    calculateCrcP01(ConfigPtr, receivedCounter, DataPtr);

                if (isCheckOfReceivedDataNotOkP01(ConfigPtr, StatePtr,
                    receivedCounter, receivedCrc, calculatedCrc,
                    receivedDataIDNibble) == TRUE) {
                    status = E2E_E_OK;  // Status already set inside
                } else {
                    doChecksP01(ConfigPtr, StatePtr, receivedCounter);
                }
            }
        }
    }
    return status;
}
```

First the CRC check and the first-data detection:

```c
static INLINE boolean isCheckOfReceivedDataNotOkP01(
    const E2E_P01ConfigType* ConfigPtr, E2E_P01CheckStateType* StatePtr,
    uint8 receivedCounter, uint8 receivedCrc, uint8 calculatedCrc,
    uint8 receivedDataIDNibble)
{
    boolean status = FALSE;

    if ( (receivedCrc != calculatedCrc) ||
         ( (ConfigPtr->DataIDMode == E2E_P01_DATAID_NIBBLE) &&
           (receivedDataIDNibble != ((ConfigPtr->DataID)>>8)) ) )
    {
        StatePtr->Status = E2E_P01STATUS_WRONGCRC;
        status = TRUE;
    }
    else if (isFirstDataSinceInitialisationP01(ConfigPtr,
        StatePtr, receivedCounter) == TRUE) {
        status = TRUE;  // Status set to E2E_P01STATUS_INITIAL inside
    }
    return status;
}
```

Then the core delta counter check logic:

```c
static INLINE void doChecksP01(const E2E_P01ConfigType* ConfigPtr,
    E2E_P01CheckStateType* StatePtr, uint8 receivedCounter)
{
    uint8 delta;
    delta = calculateDeltaCounterP01(receivedCounter,
        StatePtr->LastValidCounter);

    if (delta == 0) {
        // REPEATED: duplicate message received
        if (StatePtr->NoNewOrRepeatedDataCounter < MAX_P01_COUNTER_VALUE) {
            StatePtr->NoNewOrRepeatedDataCounter++;
        }
        StatePtr->Status = E2E_P01STATUS_REPEATED;
    }
    else if (delta == 1) {
        // OK: counter is exactly consecutive
        StatePtr->MaxDeltaCounter = ConfigPtr->MaxDeltaCounterInit;
        StatePtr->LastValidCounter = receivedCounter;
        StatePtr->LostData = 0;
        if (StatePtr->NoNewOrRepeatedDataCounter
            <= ConfigPtr->MaxNoNewOrRepeatedData) {
            StatePtr->NoNewOrRepeatedDataCounter = 0;
            if (StatePtr->SyncCounter > 0) {
                StatePtr->SyncCounter--;
                StatePtr->Status = E2E_P01STATUS_SYNC;
            } else {
                StatePtr->Status = E2E_P01STATUS_OK;
            }
        } else {
            StatePtr->NoNewOrRepeatedDataCounter = 0;
            StatePtr->SyncCounter = ConfigPtr->SyncCounterInit;
            StatePtr->Status = E2E_P01STATUS_SYNC;
        }
    }
    else if (delta <= StatePtr->MaxDeltaCounter) {
        // OKSOMELOST: frames lost but still within tolerance
        StatePtr->MaxDeltaCounter = ConfigPtr->MaxDeltaCounterInit;
        StatePtr->LastValidCounter = receivedCounter;
        StatePtr->LostData = delta - 1;
        // ... SyncCounter logic ...
        StatePtr->Status = E2E_P01STATUS_OKSOMELOST;
    }
    else {
        // WRONGSEQUENCE: beyond tolerance
        StatePtr->SyncCounter = ConfigPtr->SyncCounterInit;
        StatePtr->Status = E2E_P01STATUS_WRONGSEQUENCE;
    }
}
```

The delta counter wrap calculation (handling the 0xE→0x0 jump):

```c
static INLINE uint8 calculateDeltaCounterP01(
    uint8 receivedCounter, uint8 lastValidCounter)
{
    uint8 res;
    res = 0;
    if (receivedCounter >= lastValidCounter) {
        res = receivedCounter - lastValidCounter;
    }
    else {
        res = MAX_P01_COUNTER_VALUE + 1 + receivedCounter
            - lastValidCounter;
    }
    return res;
}
```

`MAX_P01_COUNTER_VALUE` = 14 (that is, 0xE). When `receivedCounter=0, lastValidCounter=14`: `res = 14+1+0-14 = 1`, correctly identified as consecutive. delta=0 → duplicate, delta=1 → normal consecutive, 1<delta≤MaxDelta → frames lost, delta>MaxDelta → out of order.

## 7. E2E_SM.c: The Sliding-Window State Machine

The E2E State Machine is independent of the profile; it cares only about the accumulated statistics of past Check results:

```c
static INLINE void E2E_SMAddStatus(E2E_PCheckStatusType ProfileStatus,
    E2E_SMCheckStateType* StatePtr, uint8 windowSize)
{
    StatePtr->ProfileStatusWindow[StatePtr->WindowTopIndex]
        = (uint8)ProfileStatus;

    count=0;
    for (i=0; i<windowSize; i++) {
        if (StatePtr->ProfileStatusWindow[i] == (uint8)E2E_P_OK) {
            count++;
        }
    }
    StatePtr->OkCount = count;

    count=0;
    for (i=0; i<windowSize; i++) {
        if (StatePtr->ProfileStatusWindow[i] == (uint8)E2E_P_ERROR) {
            count++;
        }
    }
    StatePtr->ErrorCount = count;

    if (StatePtr->WindowTopIndex >= (windowSize-1)) {
        StatePtr->WindowTopIndex = 0;
    } else {
        StatePtr->WindowTopIndex++;
    }
}
```

This is a fixed-width sliding window. After each AddStatus it recounts the OK and ERROR entries in the window, then transitions according to the current SMState:

```c
static INLINE void E2E_SMCheck_VALID(const E2E_SMConfigType* ConfigPtr,
    E2E_SMCheckStateType* StatePtr)
{
    if ((StatePtr->ErrorCount <= ConfigPtr->MaxErrorStateValid)
        && (StatePtr->OkCount >= ConfigPtr->MinOkStateValid)) {
        StatePtr->SMState = E2E_SM_VALID;
    } else {
        StatePtr->SMState = E2E_SM_INVALID;
    }
}
```

The enum has five states in total; the fifth, `E2E_SM_DEINIT`, means `E2E_SMCheckInit` has not been called yet, in which case `E2E_SMCheck` returns `E2E_E_WRONGSTATE` directly and performs no transition. The transition logic of the other four states:

- **NODATA**: receives a status other than NONEWDATA/ERROR → enter INIT
- **INIT**: ErrorCount ≤ MaxErrorStateInit && OkCount ≥ MinOkStateInit → VALID; ErrorCount > MaxErrorStateInit → INVALID
- **VALID**: ErrorCount ≤ MaxErrorStateValid && OkCount ≥ MinOkStateValid → stay VALID; otherwise → INVALID
- **INVALID**: ErrorCount ≤ MaxErrorStateInvalid && OkCount ≥ MinOkStateInvalid → VALID

The window size is compile-time configuration. For example, WindowSize=5, MinOkStateValid=3, MaxErrorStateValid=1 means at least 3 of 5 frames OK and at most 1 ERROR keeps it VALID.

## 8. MapStatusToSM: Profile Status → Generic Status

`E2E_P01MapStatusToSM` supports two behavior modes, following the specification change around ASR 4.2.2:

```c
E2E_PCheckStatusType E2E_P01MapStatusToSM(
    Std_ReturnType CheckReturn, E2E_P01CheckStatusType Status,
    boolean profileBehavior)
{
    E2E_PCheckStatusType retValue = E2E_P_ERROR;

    if (CheckReturn != E2E_E_OK) {
        retValue = E2E_P_ERROR;
    }
    else if (profileBehavior == TRUE) {
        // ASR4.2.2+ behavior
        switch(Status) {
            case E2E_P01STATUS_OK:
            case E2E_P01STATUS_OKSOMELOST:
            case E2E_P01STATUS_SYNC:
                retValue = E2E_P_OK; break;
            case E2E_P01STATUS_REPEATED:
                retValue = E2E_P_REPEATED; break;
            case E2E_P01STATUS_NONEWDATA:
                retValue = E2E_P_NONEWDATA; break;
            case E2E_P01STATUS_WRONGSEQUENCE:
            case E2E_P01STATUS_INITIAL:
                retValue = E2E_P_WRONGSEQUENCE; break;
        }
    }
    else {
        // Pre-ASR4.2.2 behavior: INITIAL maps to OK, SYNC to WRONGSEQUENCE
        switch(Status) {
            case E2E_P01STATUS_OK:
            case E2E_P01STATUS_OKSOMELOST:
            case E2E_P01STATUS_INITIAL:
                retValue = E2E_P_OK; break;
            case E2E_P01STATUS_REPEATED:
                retValue = E2E_P_REPEATED; break;
            case E2E_P01STATUS_NONEWDATA:
                retValue = E2E_P_NONEWDATA; break;
            case E2E_P01STATUS_WRONGSEQUENCE:
            case E2E_P01STATUS_SYNC:
                retValue = E2E_P_WRONGSEQUENCE; break;
        }
    }
    return retValue;
}
```

The key difference between old and new behavior: the old version treats INITIAL as OK (lenient startup) and SYNC as WRONGSEQUENCE (strict synchronization); the new version treats INITIAL as WRONGSEQUENCE (strict startup) and SYNC as OK (lenient synchronization transition). A `profileBehavior` boolean keeps backward compatibility. This "dual-mode compile support" is common as AUTOSAR specifications evolve.

The essence of the E2E library is not a single CRC calculation or counter embedding; it is the "dependency-free pure function" architecture. `E2E_P01Check` only answers "is this frame correct"; `E2E_SMCheck` answers "can the behavior of the last N frames be trusted". The two layers are independently testable and independently certifiable. No dynamic memory allocation, no function-pointer callbacks, no recursion — just const configuration + pure functions + a finite state machine.

## Summary

1. The E2E library is a pure function library. It calls no RTE or BSW modules, depends only on `Crc.h` and `Std_Types.h`, and can be certified independently as an SEooC. All errors travel through return values, with no DET/DEM reporting.
2. `E2E_P01Protect` and `E2E_P01Check` follow the same three-stage pattern: configuration validation (`checkConfigP01`) → CRC calculation (DataID + data, skipping the CRC byte itself) → counter embedding/extraction. CRC8 uses the SAE J1850 polynomial 0x1D.
3. On the Check side, `calculateDeltaCounterP01` handles the 0xE→0x0 wrap. delta=0 means duplicate, delta=1 means consecutive, delta≤MaxDelta means frames lost, and delta>MaxDelta means out of order, covering every communication fault mode.
4. The `E2E_SM` state machine is independent of the profile type. It counts OK/ERROR over the last N frames in a fixed-width sliding window. The enum has five states; `DEINIT` is the state before initialization. The path runs NODATA→INIT→VALID, and VALID and INVALID switch back and forth according to the window statistics. Window size and thresholds are all compile-time configuration.
5. `E2E_P01MapStatusToSM` uses the `profileBehavior` parameter to support the behavior difference before and after ASR 4.2.2 (where INITIAL/SYNC map to OK/WRONGSEQUENCE), giving the specification backward compatibility.
