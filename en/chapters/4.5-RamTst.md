# 4.5 RamTst: The Silicon's Physician

## Scenario: The 0.3-Second Decision at Power-Up

The ECU powers up. The 12 V vehicle supply flows through the regulator, producing 3.3 V and 1.8 V for the SoC. The PMU releases the reset signal and the Cortex-R5 starts executing from BootROM. The FSBL (First Stage Bootloader) initializes the PLL and the DDR controller and loads the application. Then, before any application code, it calls `RamTst_Init()`, and after that `RamTst_RunFullTest()` starts walking every memory cell in SRAM.

If any bit is stuck at 0 or stuck at 1 (stuck-at fault), if coupling exists between any two adjacent cells (coupling fault), if any address-line decoder is wrong, the ECU will not enter normal operation. RamTst is the silicon's physician, and its diagnosis directly decides whether the ECU can "go on the road".

## 1. RamTst.c: Architecture Overview

`memory/RamTst/src/RamTst.c`, 561 lines. The internal state struct:

```c
typedef struct {
    RamTst_TestResultType
        RamTst_BlockResultBuffer[RAMTST_NUM_BLOCKS];
    RamTst_ExecutionStatusType ExecStatus;
#if (RAMTST_STOP_API == STD_ON)
    RamTst_ExecutionStatusType OrderedStatus;
#endif
    RamTst_AlgParamsIdType ActiveAlgParamID;
    RamTstInitInitStatus InitStatus;
    RamTst_TestResultType CurrentTestResult;
} RamTstInternalType;

static RamTstInternalType RamTst_Internal = {
    .ExecStatus = RAMTST_EXECUTION_UNINIT,
    .ActiveAlgParamID = 0,
    .InitStatus = RAMTST_UNINIT,
    .CurrentTestResult = RAMTST_RESULT_NOT_TESTED
};
```

The internal state machine has three dimensions:
- **ExecutionStatus**: UNINIT → STOPPED → RUNNING (→ STOPPED), plus a SUSPENDED value in the enum that is never assigned
- **InitStatus**: UNINIT / INIT (a separate initialization flag)
- **CurrentTestResult**: NOT_TESTED / OK / NOT_OK / UNDEFINED

This three-layer state machine catches wrong API call order; whether it can block the call depends on the DET switch:

```c
#if ( RAMTST_DEV_ERROR_DETECT == STD_ON )
#define VALIDATE(_exp,_api,_err ) \
        if( !(_exp) ) { \
            (void)Det_ReportError(RAMTST_MODULE_ID,0,_api,_err); \
            return; \
        }
#define VALIDATE_W_RV(_exp,_api,_err,_rv ) \
        if( !(_exp) ) { \
          (void)Det_ReportError(RAMTST_MODULE_ID,0,_api,_err); \
          return (_rv); \
        }
#else
#define VALIDATE(_exp,_api,_err )
#define VALIDATE_W_RV(_exp,_api,_err,_rv )
#endif
```

The VALIDATE macros are of the same family as WdgM's CHECK macros: with DET on they report an error and return immediately, and with DET off they degrade to empty macros. An empty macro means the `_exp` condition and the return vanish from the compiled output together, the function body has no timing protection left, and only the integrator can guarantee the call order.

## 2. Init: Preparing the Examination Equipment

```c
void RamTst_Init(void)
{
    RamTst_Internal.InitStatus = RAMTST_INIT;
    VALIDATE( ( RAMTST_EXECUTION_UNINIT
        == RamTst_Internal.ExecStatus ),
        RAMTST_INIT_SERVICE_ID, RAMTST_E_STATUS_FAILURE);

    RamTst_Internal.ExecStatus = RAMTST_EXECUTION_STOPPED;
    RamTst_Internal.ActiveAlgParamID =
        RamTst_ConfigParams.RamTstDefaultAlgParamsId;

    for( RamTst_NumberOfBlocksType i = 0;
         i < RAMTST_NUM_BLOCKS; i++ ) {
        RamTst_Internal.RamTst_BlockResultBuffer[i]
            = RAMTST_RESULT_NOT_TESTED;
    }
    RamTst_Internal.CurrentTestResult = RAMTST_RESULT_NOT_TESTED;
}
```

Preconditions for Init: `ExecStatus == UNINIT`; it can only be entered from the uninitialized state. After Init it goes to STOPPED (ready but no test run). `RamTstDefaultAlgParamsId` selects the default algorithm parameter set from the configuration.

One detail: `InitStatus` is set to INIT at the **start** of the function, before VALIDATE. This is not a bug. If VALIDATE fails (say Init is called twice and `ExecStatus` is no longer UNINIT), the function returns immediately, but `InitStatus == RAMTST_INIT`, while loading the default parameter set, clearing the block results, and resetting `CurrentTestResult` are all skipped; the module keeps working as it was. With DET off there isn't even that error record, and the integrator must ensure Init is called exactly once after UNINIT.

## 3. RunFullTest: The Execution Engine

This is the core of the module, a seventy-line test scheduler:

```c
void RamTst_RunFullTest( void )
{
    VALIDATE( ( RamTst_Internal.InitStatus != RAMTST_UNINIT ),
        RAMTST_INIT_SERVICE_ID, RAMTST_E_UNINIT);
    VALIDATE( ( (RAMTST_EXECUTION_STOPPED)
        == RamTst_Internal.ExecStatus ),
        RAMTST_RUNFULLTEST_SERVICE_ID, RAMTST_E_STATUS_FAILURE);

    const RamTst_AlgParamsType *algParams = NULL;

    /* Find config for the active algorithm */
    for(RamTst_AlgParamsIdType i = 0;
        (i < RamTst_ConfigParams.RamTstNumberOfAlgParamSets)
        && (NULL == algParams); i++) {
        if( RamTst_ConfigParams.RamTstAlgParams[i].RamTstAlgParamsId
            == RamTst_Internal.ActiveAlgParamID ) {
            algParams = &RamTst_ConfigParams.RamTstAlgParams[i];
        }
    }

    if( NULL != algParams ) {
        RamTst_Internal.ExecStatus = RAMTST_EXECUTION_RUNNING;
        RamTst_Internal.CurrentTestResult = RAMTST_RESULT_UNDEFINED;

        /* Initialize all block results to NOT_TESTED */
        for(RamTst_NumberOfBlocksType i = 0;
            i<algParams->RamTstNumberOfBlocks;i++)
        {
            RamTst_Internal.RamTst_BlockResultBuffer[
                algParams->RamTstBlockParams[i].RamTstBlockIndex]
                = RAMTST_RESULT_NOT_TESTED;
        }

        /* Run test for each block */
        for(RamTst_NumberOfBlocksType i = 0;
            i < algParams->RamTstNumberOfBlocks; i++)
        {
            RamTst_TestResultType res;

            switch(algParams->RamTstAlgorithm) {
#if (RAMTST_MARCH_TEST_SELECTED == STD_ON)
                case RAMTST_MARCH_TEST:
                    res = ramTstMarchX(
                        algParams->RamTstBlockParams[i]
                            .RamTstStartAddress.dataPtr,
                        algParams->RamTstBlockParams[i]
                            .RamTstEndAddress.dataPtr);
                    break;
#endif
                default:
                    res = RAMTST_RESULT_NOT_OK;
                    break;
            }

            if(res != RAMTST_RESULT_OK){
#if defined(USE_DEM)
                if(DEM_EVENT_ID_NULL
                   != RamTst_ConfigParams.RAMTST_E_RAM_FAILURE) {
                    (void)Dem_ReportErrorStatus(
                        RamTst_ConfigParams.RAMTST_E_RAM_FAILURE,
                        DEM_EVENT_STATUS_FAILED);
                }
#endif
                RamTst_Internal.CurrentTestResult
                    = RAMTST_RESULT_NOT_OK;
            }
            RamTst_Internal.RamTst_BlockResultBuffer[
                algParams->RamTstBlockParams[i].RamTstBlockIndex]
                = res;
        }

        if( RAMTST_RESULT_UNDEFINED
            == RamTst_Internal.CurrentTestResult ) {
            RamTst_Internal.CurrentTestResult = RAMTST_RESULT_OK;
        }
        RamTst_Internal.ExecStatus = RAMTST_EXECUTION_STOPPED;
    }
}
```

Scheduling flow:
1. Look up the algorithm configuration through `ActiveAlgParamID`
2. Switch state to RUNNING
3. Walk all blocks, running the configured algorithm
4. Record the result per block
5. Any block failure → report a DEM event and mark NOT_OK
6. All pass → OK
7. Return state to STOPPED

Note that `CurrentTestResult` is initialized to `UNDEFINED`. If it is still UNDEFINED when the whole test finishes, no block failed, so it is set to OK. As soon as one block fails, it is set to NOT_OK.

## 4. ramTstMarchX: The Four-Step Examination

This is the technical core of the section, the March X algorithm in C:

```c
static RamTst_TestResultType ramTstMarchX(uint32 *sa, uint32 *ea)
{
    RamTst_TestResultType status;
    boolean ret;
    uint32 *ptr_start;
    uint32 *ptr_end;

    status = RAMTST_RESULT_OK;
    ptr_end = ea;
    ptr_start = sa;
    ret = TRUE;

    /* Step1: write 0 with up addressing order */
    for( ;ptr_start < ptr_end; ptr_start++){
        *ptr_start = 0;
    }

    /* Step2: read 0 and write 1 with up addressing order */
    ptr_start = sa;
    for( ;ptr_start < ptr_end; ptr_start++){
        if(0 != *ptr_start){
            status = RAMTST_RESULT_NOT_OK;
            ret = FALSE;
            break;
        }
        *ptr_start = 1;
    }

    if (ret == TRUE) {
        /* Step3: read 1 and write 0 with down addressing order */
        ptr_start = sa;
        ptr_end--;
        for( ; ptr_end >= ptr_start; ptr_end--){
            if(1 != *ptr_end){
                status = RAMTST_RESULT_NOT_OK;
                ret = FALSE;
                break;
            }
            *ptr_end = 0;
        }

        if (ret == TRUE) {
            /* Step4: read 0 with down addressing order */
            ptr_end = ea;
            ptr_end--;
            for( ; ptr_end >= ptr_start; ptr_end--){
                if(0 != *ptr_end){
                    status = RAMTST_RESULT_NOT_OK;
                    break;
                }
            }
        }
    }
    return status;
}
```

Each of the four steps catches a specific fault model:

| Step | Operation | Addressing direction | Fault model detected |
|------|------|---------|--------------|
| Step 1 | Write all 0 | Ascending | Establishes a known initial value; makes no judgment itself |
| Step 2 | Read 0→write 1 | Ascending | Cells stuck at 1, cells that will not take a 0 |
| Step 3 | Read 1→write 0 | **Descending** | Cells stuck at 0, cells that will not transition 0→1 |
| Step 4 | Read 0 | **Descending** | Cells that will not transition 1→0, coupling faults caused by neighboring cells |

Why must Step 3 and Step 4 go **descending**? The key is coupling faults: when one cell is dragged along by a read/write to a neighboring cell, whether you can see it depends on the order of the two operations. Sweeping in one direction only, the order between the aggressor cell's operation and the victim cell's operation is fixed, and some combinations are masked by the order itself; sweep in the opposite direction and that pair of orders reverses, so the masking disappears. The standard makes the same point when it discusses RAM March tests: the coverage of chained (coupling) cells depends on the write/read order. The whole March X suite targets four classes: stuck-at faults, transition faults, addressing faults, and linked-cell faults. Only the two directions together give the full coverage.

**The `ptr_end--` detail in Step 3**: `ea` points to "the next address after the last one" (end-after), so at the start of the descending pass the code first does `ptr_end--` to point at the real last location.

## 5. SelectAlgParams: Hot-Swapping the Test Strategy

`RamTst_SelectAlgParams` allows switching the algorithm at runtime, but not while RUNNING:

```c
void RamTst_SelectAlgParams( RamTst_AlgParamsIdType NewAlgParamsId )
{
    VALIDATE( ( RamTst_Internal.InitStatus != RAMTST_UNINIT ),
        RAMTST_SELECTALGPARAMS_SERVICE_ID, RAMTST_E_UNINIT);
    VALIDATE( ( RamTst_Internal.ExecStatus
        == RAMTST_EXECUTION_STOPPED ),
        RAMTST_SELECTALGPARAMS_SERVICE_ID,
        RAMTST_E_STATUS_FAILURE);

    /* Check parameter NewAlgParamsId */
    const RamTst_AlgParamsType *algParams = NULL;
    for(RamTst_AlgParamsIdType i = 0;
        (i < RamTst_ConfigParams.RamTstNumberOfAlgParamSets)
        && (NULL == algParams); i++) {
        if( RamTst_ConfigParams.RamTstAlgParams[i].RamTstAlgParamsId
            == NewAlgParamsId ) {
            algParams = &RamTst_ConfigParams.RamTstAlgParams[i];
            for(RamTst_NumberOfBlocksType block = 0;
                block < algParams->RamTstNumberOfBlocks; block++) {
                RamTst_Internal.RamTst_BlockResultBuffer[
                    algParams->RamTstBlockParams[block]
                        .RamTstBlockIndex]
                    = RAMTST_RESULT_NOT_TESTED;
            }
            RamTst_Internal.ActiveAlgParamID = NewAlgParamsId;
            RamTst_Internal.ExecStatus
                = RAMTST_EXECUTION_STOPPED;
            RamTst_Internal.CurrentTestResult
                = RAMTST_RESULT_NOT_TESTED;
        }
    }
    VALIDATE( ( NULL != algParams ),
        RAMTST_SELECTALGPARAMS_SERVICE_ID,
        RAMTST_E_OUT_OF_RANGE);
}
```

The function body logic is complete: find the parameter set, clear the result cache, update ActiveAlgParamID, and a call made in the RUNNING state is blocked by the VALIDATE guard above. But in this source, the only algorithm that can actually run after switching is March X: the `RunFullTest` switch accepts only the MARCH branch, and every other algorithm falls into default and is judged NOT_OK outright. The example configuration shipped with the repo also turns the switch interface off as STD_OFF, so this function does not even compile, and that configuration has only one parameter set anyway. What is real is that the switch automatically clears the target blocks' result cache and ensures that stale results do not mislead later reads.

## 6. The Other Algorithm Interfaces: Unimplemented "Reserved Slots"

Arctic Core defines the framework for several test algorithms but implements only March X:

```c
#if (RAMTST_GALPAT_TEST_SELECTED == STD_ON)
RamTst_TestResultType RamTst_Galpat(...) { /* Not supported */ }
#endif
#if (RAMTST_ABRAHAM_TEST_SELECTED == STD_ON)
RamTst_TestResultType RamTst_Abraham(...) { /* Not supported */ }
#endif
#if (RAMTST_TRANSP_GALPAT_TEST_SELECTED == STD_ON)
RamTst_TestResultType RamTst_Transp_Galpat(...) { /* Not supported */ }
#endif
#if (RAMTST_WALK_PATH_TEST_SELECTED == STD_ON)
RamTst_TestResultType RamTst_Walk_Path(...) { /* Not supported */ }
#endif
#if (RAMTST_CHECKERBOARD_TEST_SELECTED == STD_ON)
RamTst_TestResultType RamTst_CheckerBoard(...) { /* Not supported */ }
#endif
```

These are compile-time placeholder function bodies, the comment literally says Not supported, and all five switches in the example configuration are STD_OFF while only the March test is on. Wanting another algorithm takes more than flipping a switch: the function body is empty (and declares a return value without a return statement), and `RunFullTest`'s switch has no matching branch, so the result would simply be NOT_OK for every block. March X covers stuck-at, transition, addressing, and coupling faults. The standard records the typical diagnostic coverage of a RAM March test as High, while noting that it is ineffective against soft errors and has zero coverage of transient faults, so it generally fits only power-up initialization or shutdown. The standard also does not bind any particular memory test algorithm to any ASIL level.

## 7. GetTestResultPerBlock: Fault Localization Down to the Block

After the test completes, `RamTst_GetTestResultPerBlock` lets you query the result of a specific memory block:

```c
RamTst_TestResultType RamTst_GetTestResultPerBlock(
    RamTst_NumberOfBlocksType BlockID)
{
    // ... init check ...
    const RamTst_BlockParamsType *blockParamPtr = NULL;
    const RamTst_AlgParamsType *algParams = NULL;

    for(RamTst_AlgParamsIdType i = 0;
        (i < RamTst_ConfigParams.RamTstNumberOfAlgParamSets)
        && (NULL == blockParamPtr); i++) {
        algParams = &RamTst_ConfigParams.RamTstAlgParams[i];
        for(RamTst_NumberOfBlocksType block = 0;
            (block < algParams->RamTstNumberOfBlocks)
            && (NULL == blockParamPtr); block++) {
            if(algParams->RamTstBlockParams[block].RamTstBlockId
               == BlockID) {
                blockParamPtr =
                    &algParams->RamTstBlockParams[block];
            }
        }
    }

    if(NULL != blockParamPtr) {
        status = RamTst_Internal.RamTst_BlockResultBuffer[
            blockParamPtr->RamTstBlockIndex];
    } else {
        status = RAMTST_RESULT_UNDEFINED; // Invalid block id
        // DET report if enabled...
    }
    return status;
}
```

A two-level loop: first find the algorithm parameter set, then find the block inside it. If the BlockID does not exist, it returns UNDEFINED and reports through DET. This lets diagnostic tools pinpoint "which memory block is broken" instead of saying vaguely that "RAM has a problem".

RamTst's design philosophy is "better a false diagnosis than a missed one". March X's four-step sequence covers stuck-at, transition, addressing, and coupling faults, at the cost of four passes and about 4n memory accesses (n is the number of words in the block), which is entirely acceptable for a one-time check at startup. `RunFullTest`'s "UNDEFINED initial value → set OK or failure" pattern ensures there is no false negative of the "forgot to set the result, so it is considered OK" kind: unsafe by default, safe only after explicit verification.

## Summary

1. RamTst maintains a three-layer internal state machine: `ExecutionStatus` (UNINIT→STOPPED→RUNNING, plus a SUSPENDED value in the enum that is never assigned), `InitStatus` (UNINIT/INIT), and `CurrentTestResult` (NOT_TESTED/OK/NOT_OK/UNDEFINED). Wrong call order is caught and reported by the VALIDATE macros when DET is on; with DET off that protection disappears entirely and only the integrator can guarantee the order.
2. The March X algorithm detects faults in four passes: Step 1 writes all 0 in ascending order to establish a known initial value → Step 2 reads 0 and writes 1 in ascending order (catches cells stuck at 1) → Step 3 reads 1 and writes 0 in descending order (catches cells stuck at 0 and transition faults) → Step 4 reads 0 in descending order (catches coupling faults caused by neighboring cells). Only ascending plus descending together give full coverage; the standard says plainly that coverage of linked cells depends on the write/read order.
3. `RunFullTest` uses a default-unsafe strategy: "UNDEFINED initial value → per-block test → explicit OK/NOT_OK". Only after every block passes does UNDEFINED turn into OK; any block failure marks NOT_OK and reports a DEM event.
4. `RamTst_SelectAlgParams` can switch the algorithm parameter set in the STOPPED state and clears the target blocks' result cache; a call in the RUNNING state is blocked. But in this source, only March X can actually run after the switch, and the example configuration both disables this interface and configures only one parameter set.
5. Arctic Core leaves five placeholder function bodies reading Not supported for Galpat, Abraham, Transparent Galpat, Walk Path, and Checkerboard. All five switches are off in the example configuration, and only March X is implemented and on by default. The standard records the typical coverage of a RAM March test as High, while noting that it is ineffective against soft errors and has zero coverage of transient faults; whether that is enough has to be argued in the project's own failure analysis.
